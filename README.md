# TrainCov

PWA, що для обраного залізничного рейсу в Польщі показує, **де і коли зникне мобільний інтернет**.

План MVP — [docs/00-PLAN.md](docs/00-PLAN.md). Поточний стан: **задача 06** (прогноз: countdown
до наступної діри, часові мітки на всій стрічці, dead reckoning у тунелі).

## Запуск

```bash
npm install
npm run pipeline       # GTFS → public/data/ (потрібен один раз перед dev)
npm run dev            # http://localhost:5173  (і по LAN — host увімкнено)
npm run dev:https      # те саме, але HTTPS (self-signed) — для тестів на телефоні
npm run build          # tsc -b && vite build
npm run preview        # прод-збірка локально, :4173
npm test               # vitest: eta.ts, стрічка, прогон симулятора
npm run typecheck
npm run lint
```

## Тест на телефоні

`server.host` увімкнено, тому dev-сервер одразу слухає LAN — бери адресу з рядка `Network:`,
який Vite друкує при старті.

**HTTPS потрібен** для `navigator.geolocation` і Wake Lock API (задачі 04 і 07) — на iOS обидва
працюють лише в secure context. Обраний спосіб:

1. **Основний — `npm run dev:https`** (`@vitejs/plugin-basic-ssl`). Відкрити
   `https://<IP-мака>:5173`, у Safari прийняти самопідписаний сертифікат
   («Показати деталі» → «Відвідати цей сайт»).
2. **Запасний — тунель**, якщо Safari упреться в сертифікат або треба показати когось ззовні:
   ```bash
   cloudflared tunnel --url http://localhost:5173
   ```
   Тунель дає справжній HTTPS-домен, сертифікат приймати не треба.

## Симулятор поїздки

Ловити баги трекінгу в реальному потязі — дорого, тому є симулятор: він рухає «потяг» по
геометрії маршруту зі швидкістю з розкладу.

```
http://localhost:5173/?sim=1                 віртуальний час ×10
http://localhost:5173/?sim=1&simScale=20     ×20 (максимум)
http://localhost:5173/?sim=1&simKm=190       старт із 190-го км
```

- Обрати рейс на **Рейс** → вкладка **Дорога** → «Почати поїздку». Дозвіл на геолокацію не
  потрібен — реальний `watchPosition` у цьому режимі не викликається взагалі.
- Час у симуляторі **віртуальний** і біжить швидше за реальний, зокрема й у мітках фіксів.
  Тому швидкість на екрані дорівнює профільній (а не помноженій на масштаб), а 30-секундне
  протухання фіксів чекати по-справжньому не треба.
- На станціях потяг стоїть стільки, скільки в розкладі (мінімум 2 хв) → статус `стоїмо`.
- На першій відчутній мертвій зоні (`severity: none`, ≥ 1 км; якщо таких немає — на 40%
  маршруту, 3 км) фікси зникають → статус `немає GPS`. Через 30 c вмикається dead reckoning:
  км їде далі за останньою швидкістю, поруч висить бейдж `км — оцінка`. Так перевіряється
  поведінка в тунелі.
- Позиції йдуть із гаусовим шумом ~15 м, тож `offset` від колії на екрані ненульовий.

## Дані маршрутів

`npm run pipeline` качає зведений GTFS усіх польських залізничних перевізників
(`https://mkuran.pl/gtfs/polish_trains.zip`, ~32 МБ) у `.cache/`, ріже його на
маленькі бандли і кладе у `public/data/`:

```
public/data/
  index.json               список рейсів для UI
  routes/{tripId}.json     RouteBundle: shape, stops[].km, speedProfile, deadZones
```

- Zip кешується на 24 год; `npm run pipeline -- --force-download` перекачує примусово.
- Мертві зони добираються з Overpass і з ручного файлу — див. «Мертві зони» нижче.
- Клієнт **ніколи** не парсить GTFS — тільки готові бандли (кожен < 30 КБ).
- Які напрямки збирати — [scripts/pipeline/config.ts](scripts/pipeline/config.ts) (`TARGET`).
- Типи бандла — [src/core/types.ts](src/core/types.ts), спільні для пайплайна й апки.
- `public/data/` (~650 КБ) комітиться в git: тоді `npm install && npm run dev` працює одразу,
  а деплой на Cloudflare Pages не потребує Node-кроку. Кеш `.cache/` — навпаки, в `.gitignore`.

### Трекінг (задача 04)

- `linref.ts` шукає найближчу точку колії **у вікні ±100 сегментів** навколо попередньої —
  0.26 мс на фікс і, головне, без стрибків на самоперетинах геометрії (вокзальні горловини).
  Відкат назад більший за 300 м ігнорується: потяг не їде назад, це шум.
- `speed.ts`: `coords.speed` → інакше похідна Δkm/Δt (Android у WebView часто дає `null`),
  EMA α=0.15, кламп 0–220. Немає фіксів 30 c → `немає GPS`. Швидкість < 3 км/год протягом
  20 c → `стоїмо`.
- `trip-tracker.ts` — стан **поза React**. На кожен фікс ререндериться лише `TripStatusBar`;
  стрічка й маркер на карті оновлюються імперативно (`useTripUpdates`), без ререндера.
- Далі 500 м від колії → статус `не на маршруті`, банер, і такі фікси не йдуть в оцінювач
  швидкості (км там усе одно сміття).

### Мертві зони (задача 05)

Два детерміновані джерела, обидва — на етапі збірки, клієнт нічого не рахує.

**OSM (Overpass).** bbox маршруту (+0.02°) ріжеться на плитки глобальної сітки 2°, у кожній
беруться `railway` з `tunnel=yes` / `cutting=yes`. Way визнається «нашим», якщо ≥ 80% його вершин
лежать ближче 50 м до shape; km зони — мін/макс проєкцій вершин. Сегменти ближче 0.2 км
зливаються (двоколійна лінія = 2 ways, довгий тунель — десятки). Виїмки коротші 0.15 км
відкидаються, тунелі лишаються будь-якої довжини. `tunnel` → `severity: none`, `cutting` → `weak`.

- **Плитки, а не цілий bbox**: на bbox Poznań→Wien (10°×9°) Overpass стабільно віддає 504.
  Межі плиток кратні 2°, тому різні маршрути через один регіон дають однаковий запит і ділять
  кеш: 33 бандли — це лише 23 унікальні плитки.
- Відповіді кешуються в `.cache/overpass/` на 30 днів → **повторний прогін пайплайна не робить
  жодного мережевого запиту** (холодний старт ~25 хв, теплий — 10 c). Кеш-ключ — текст запиту,
  тож зміна QL інвалідовує його.
- Два дзеркала (`overpass-api.de`, `overpass.kumi.systems`), 5 спроб з експоненційним беквофом
  (4→64 c): під навантаженням 504/502 сипляться регулярно, і без беквофу дані просто губляться.
  Overpass без `User-Agent` відповідає 406 — заголовок обов'язковий.
- `npm run pipeline -- --no-osm` — працювати тільки з кеша (офлайн / CI без мережі).
- Плитка без відповіді — не помилка збірки, але про неї є окремий `⚠` у логах: мовчазна дірка
  в даних гірша за їх відсутність.

**Ручний файл.** [scripts/pipeline/manual-zones.json](scripts/pipeline/manual-zones.json) —
власні спостереження. `fromKm`/`toKm` тут — км **конкретного бандла**, тому `match` має фіксувати
напрямок (масив `tripNameContains`, збігтися мають усі підрядки). Manual пріоритетніший: там, де
він перетинається з OSM, OSM-шматок вирізається. Стартові записи — сід-дані, позначені в `note`.

Валідація: `0 ≤ fromKm < toKm ≤ lengthKm`, інакше зона відкидається з `⚠` у логах. На виході
зони відсортовані й не перетинаються; у бандлі кожна вже має `lengthKm` і `geometry`
(`lineSliceAlong`), у `index.json` — `zonesCount`. Поточний результат: **319 зон на 33 бандли**
(308 з OSM: 287 тунелів + 21 виїмка, 11 ручних), максимум 17 зон на рейс.

UI: на стрічці — смуга по колії (червона штрихована `none`, янтарна `weak`) з чипом
`⛔ 2.2 км · тунель`; тап → bottom-sheet із джерелом і приміткою. На карті — два шари: лінія
зони поверх маршруту (видно впритул) і **крапка-маркер у середині зони** (видно на будь-якому
зумі: тунель на 40 м як лінія на оглядовому кадрі субпіксельний). Клік по будь-якому з них
відкриває той самий шит.

### Прогноз (задача 06)

Головна фіча: «інтернет зникне через X хв, діра триватиме Y хв».
[src/core/eta.ts](src/core/eta.ts) — чиста функція, покрита юніт-тестами.

**Модель.** Від поточного км до кінця маршруту час інтегрується по сегментах. Точки розбиття —
станції, межі мертвих зон і межі сегментів `speedProfile`, тож усередині кожного відрізка
швидкість стала. На станціях додається планова стоянка (`dep - arr`) — і саме тому ETA станції
це прибуття, а не відправлення.

**Три режими деградації**, від найточнішого до найчеснішого:

| `source` | Коли | Швидкість |
|---|---|---|
| `gps` | є км і жива швидкість | перші 3 км — бленд `w·vGps + (1-w)·vProfile`, `w` спадає 1→0; далі профіль |
| `profile` | км є, швидкості немає (тунель) | чистий `speedProfile` |
| `plan` | км немає (трекінг вимкнено / не на маршруті) | планові часи з розкладу, позиція теж із розкладу |

Бленд саме такий, бо миттєва швидкість добре прогнозує близьке (потяг не встигне ні розігнатись,
ні стати), а розклад — далеке. Профіль без покривного сегмента бере сусідній, зовсім без даних —
80 км/год.

**Прив'язка розкладу до годинника.** Бандл згенеровано на одну `serviceDate`, а їхати можна
будь-коли, тож рейс ставиться на найближчий календарний день, у якому він ще не завершився
(інакше о 20:00 стрічка ранкового потяга була б порожня). Години ≥ 24 працюють як є.

**Стан хедера** — [src/core/eta-status.ts](src/core/eta-status.ts): `zone-far` (хвилини),
`zone-soon` (≤ 10 хв, великий `mm:ss`), `in-zone` (лічильник до повернення сигналу),
`no-zones`, `idle`. На межах зон гістерезис ±200 м, інакше статус миготить від GPS-шуму.

**Dead reckoning.** У тунелі GPS зникає разом зі зв'язком — саме там на екран дивляться
найпильніше. Після 30 c без фіксів трекер веде км за останньою відомою швидкістю
(`kmEstimated: true` → цифра сіріє, поруч бейдж `км — оцінка`, маркер на карті продовжує рух).
Перший же справжній фікс перебиває оцінку.

**Частоти.** `computeTripEta` — на подію трекера (фактично на фікс); секундний тік у хедері лише
віднімає `etaIn - now`; мітки на стрічці оновлюються не частіше разу на 10 c. Прогноз живе в
окремому зовнішньому сторі ([eta-store.ts](src/core/eta-store.ts)), тому щосекундний лічильник
ререндерить лише хедер, а не екран поїздки.

**Попередження** за 2 хв до діри: `navigator.vibrate(200)` + тихий 880 Гц WebAudio + флеш хедера.
Тумблер 🔔 у хедері (зберігається в `settings.etaAlerts`); AudioContext «будиться» саме на тапі —
iOS не дає створити його поза жестом. Web Notifications свідомо поза MVP.

### Стан і збереження

- IndexedDB (Dexie, база `traincov`): `bundles` — завантажені маршрути, `settings` — `operator`
  і `lastTripId`. Обраний рейс і оператор відновлюються при старті.
- **Версіонування бандлів.** Кожен збережений бандл несе `schemaVersion`
  (`BUNDLE_SCHEMA_VERSION` у [src/core/db.ts](src/core/db.ts), піднімати при зміні формату) і
  `dataVersion` (`generatedAt` з index.json). Протухла копія видаляється при читанні, старий
  формат — гуртом при старті. Без цього збережений бандл живе вічно: після задачі 05 екран
  показував «зон не знайдено» на рейсі, у якого зони вже були.
- Звірка з `dataVersion` робиться лише коли index.json уже завантажено. Офлайн порівнювати
  нема з чим, і збережена копія лишається в силі — у дорозі вона єдина.
- Повторний вибір раніше відкритого рейсу працює без мережі (бандл береться з Dexie).
- Очистити збережені пакети — екран **Логер** → «Очистити всі».
