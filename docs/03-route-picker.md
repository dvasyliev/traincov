# Задача 03 — Вибір рейсу та оператора

## Мета
Екран Home перестає бути заглушкою: пошук і вибір реального рейсу з `index.json`, вибір мобільного оператора, збереження вибору. Апка стає керованою користувачем, а не хардкодом.

## Що працює після задачі
- Home: список/пошук рейсів → тап → бандл завантажується → Trip показує саме цей маршрут.
- Обраний оператор і останній рейс зберігаються (перезапуск апки повертає стан).

## Кроки

### 3.1 Storage-шар (Dexie)
`src/core/db.ts`:
```ts
import Dexie, { type Table } from 'dexie';

export interface StoredBundle { tripId: string; savedAt: number; bundle: RouteBundle; }
export interface Settings { key: string; value: unknown; } // key: 'operator' | 'lastTripId'

class TrainCovDB extends Dexie {
  bundles!: Table<StoredBundle, string>;
  settings!: Table<Settings, string>;
  constructor() {
    super('traincov');
    this.version(1).stores({ bundles: 'tripId', settings: 'key' });
  }
}
export const db = new TrainCovDB();
```
Уже зараз бандли класти в IndexedDB (не тільки у стейт) — задача 07 отримає офлайн майже безкоштовно.

### 3.2 Завантаження index.json
- Хук `useTripIndex()`: fetch `/data/index.json`, стан `loading | error | data`. Кеш у пам'яті модуля (index маленький, у Dexie не потрібен до задачі 07).

### 3.3 UI Home
Зверху вниз:
1. **Оператор** — 4 великі чіпи: Orange / Play / Plus / T-Mobile (+ «інший»). Один вибір. Підпис дрібним: «У MVP зони спільні для всіх операторів; вибір впливає на майбутні заміри».
2. **Пошук рейсу** — одне текстове поле, фільтрує `trips[]` по підрядку в `name`/`fromStop`/`toStop` (нормалізація діакритики: `str.normalize('NFD').replace(/\p{Diacritic}/gu,'')` — щоб «wroclaw» знаходив «Wrocław»).
3. **Список рейсів** — картки: номер+назва, `14:35 → 18:12`, довжина, перевізник. Сортування за часом відправлення.
4. Тап по картці → `selectTrip(tripId)`.

### 3.4 selectTrip
```
1. Якщо bundle є в Dexie → взяти звідти, показати бейдж «збережено».
2. Інакше fetch файла з index.entry.file → зберегти в Dexie → перейти на Trip.
3. Помилка мережі → toast «Немає з'єднання. Пакет треба завантажити до поїздки.»
```
- `settings.lastTripId` оновлюється; при старті апки, якщо він є і бандл у Dexie — Home показує зверху картку «Продовжити: IC 1234 …» з кнопкою переходу на Trip.

### 3.5 Стан застосунку
- Один контекст `AppState`: `{ operator, currentTrip: RouteBundle | null, screen }` + reducer. Без Redux/Zustand — обсяг стану крихітний. (Zustand допустимий, якщо хочеться, але не додає цінності тут.)

### 3.6 Trip.tsx
- Прибрати хардкод tripId: рендерити `currentTrip` з контексту; якщо null → редірект на Home.
- Хедер: назва рейсу + чіп оператора + кнопка «змінити».

## UX-деталі
- Усі тап-цілі ≥ 44px.
- Порожній пошук → показувати всі рейси, згруповані за напрямком.
- Skeleton-стан на час завантаження index.json.

## Обмеження
- Немає вибору дати поїздки (розклад «типового дня» — див. задачу 02).
- Немає видалення збережених бандлів (додати просту кнопку «очистити всі» в Log-екрані — 10 хв роботи, корисно для дебагу).

## Acceptance criteria
- [ ] Пошук «wroclaw warszawa» без діакритики знаходить рейси.
- [ ] Вибір рейсу → Trip з правильним маршрутом; повторний вибір того ж рейсу офлайн — працює (з Dexie).
- [ ] Після перезапуску апки оператор і «Продовжити» відновлюються.
- [ ] В airplane mode Home чесно повідомляє, що новий пакет завантажити не можна.
