# Задача 04 — GPS: позиція на маршруті, швидкість, стрічка маршруту

## Мета
Серце real-time частини: GPS-координати проєктуються на колію, апка знає **поточний км маршруту** і **згладжену швидкість**, і показує це на вертикальній «стрічці маршруту» + на карті.

## Що працює після задачі
- Кнопка «Почати поїздку» → маркер «я» на карті та стрічці, поточний км (наприклад `km 45.7 / 354.2`), швидкість у км/год, прогрес до наступної станції.
- Можна перевірити пішки/в авто/симулятором — рух видно.

## Кроки

### 4.1 core/linref.ts — лінійна референція (чистий модуль, без React)
```ts
export interface RoutePosition {
  km: number;            // км уздовж маршруту від старту
  snapped: [number, number]; // точка на лінії
  offsetM: number;       // відстань від GPS-точки до колії, м
}
export function projectToRoute(shape: LineString, lng: number, lat: number): RoutePosition
```
- Реалізація: `@turf/nearest-point-on-line` → `properties.location` (km), `properties.dist` (offset, км → м).
- **Продуктивність:** turf на LineString з тисяч точок на кожен GPS-тік — ок (десятки мс), але зробити дешеву оптимізацію: тримати індекс останнього знайденого сегмента і при наступному виклику шукати лише у вікні ±100 сегментів; повний пошук — тільки якщо offset > 2 км (втратили трек). Це О(вікно) замість О(n) і прибирає стрибки на самоперетинах маршруту (вокзальні горловини).
- **Монотонність:** потяг не їде назад. Новий km < попереднього на > 0.3 км → ігнорувати оновлення (GPS-шум у тунелі/на вокзалі), лишити попередній.
- `offsetM > 500` → стан `off-route` (користувач не в потязі / не той маршрут) — показати банер.

### 4.2 core/speed.ts — швидкість
Вхід: потік `{ts, km, gpsSpeed?: number|null}`. Вихід: `speedKmh: number|null`, `confidence: 'gps'|'derived'|'none'`.
- Пріоритет 1: `position.coords.speed` (м/с), якщо не null і `accuracy` притомна → перевести в км/год.
- Пріоритет 2: похідна `Δkm/Δt` по відфільтрованих позиціях.
- Згладжування: EMA з α≈0.15 (стала часу ~30 c при тіку 5 c). Kalman не потрібен у MVP — EMA + монотонність km дають достатньо.
- Кламп 0–220; `speed < 3 км/год` протягом 20 c → стан `stopped` (стоїмо на станції/семафорі) — важливо для задачі 06.
- Немає оновлень GPS > 30 c → `confidence: 'none'` (тунель — GPS теж зникає!).

### 4.3 Хук useTrip
`src/app/useTrip.ts`:
```ts
navigator.geolocation.watchPosition(onFix, onErr, {
  enableHighAccuracy: true, maximumAge: 3000, timeout: 15000
});
```
- Стан: `{ tracking, km, speedKmh, confidence, offRoute, stopped, lastFixTs }`.
- Старт лише по тапу «Почати поїздку» (permission prompt має бути наслідком дії користувача).
- Помилки: `PERMISSION_DENIED` → екран-пояснення як увімкнути; `TIMEOUT` → просто чекати наступний фікс.
- Cleanup: `clearWatch` на unmount/стоп.

### 4.4 Симулятор (критично для розробки)
Ти не будеш їздити потягом на кожен фікс бага. `src/core/simulator.ts`:
- Режим вмикається query-параметром `?sim=1`.
- Генерує фікси кожні 2 c, рухаючись по shape зі швидкістю зі speedProfile (з зупинками на станціях по 60 c), + гаусів шум ~15 м, і з «GPS-дірою» всередині першої мертвої зони.
- Підміняє watchPosition через один інтерфейс `GeoSource` (`real | simulated`), useTrip працює з інтерфейсом.

### 4.5 UI: стрічка маршруту (RouteRibbon)
Вертикальний скрол-компонент, **основний екран Trip** (карта — другорядна вкладка):
- Вісь = км маршруту (масштаб: 1 км = N px, N підібрати ~3–4).
- Станції: горизонтальна риска + назва + плановий час.
- Маркер «я»: фіксований на ~35% висоти екрана, стрічка скролиться під ним (як у навігаторів).
- Хедер-блок: великі цифри швидкості, поточний км, статус (`їдемо / стоїмо / off-route / немає GPS`).
- Стрічку рендерити звичайним DOM/SVG (не canvas) — сегментів мало, а доступність і простота важливіші.

### 4.6 Карта
- Маркер поточної позиції (snapped точка, не сира GPS — щоб точка була «на колії»), `map.easeTo` слідування з перемикачем.

## Обмеження
- Працює лише з увімкненим екраном (Wake Lock — задача 07).
- Off-route не пропонує перевибір маршруту — лише банер.

## Пастки
- iOS Safari: watchPosition може «засинати» → якщо 30 c без фіксів і документ visible — перезапустити watch.
- `coords.speed` на Android часто null у WebView — тому derived-гілка обов'язкова.
- 100dvh + фіксований хедер: перевірити, що скрол стрічки не конфліктує з pull-to-refresh (`overscroll-behavior-y: contain`).

## Acceptance criteria
- [ ] `?sim=1`: маркер плавно їде по стрічці й карті, швидкість ≈ профільна, на станціях статус `стоїмо`.
- [ ] Реальний тест на вулиці: km і швидкість оновлюються, off-route спрацьовує за 500+ м від колії.
- [ ] У «тунелі» симулятора апка не панікує: показує `немає GPS`, km заморожений.
- [ ] Жодних ре-рендерів усього дерева на кожен GPS-тік (React DevTools profiler: оновлюються тільки хедер і маркер).
