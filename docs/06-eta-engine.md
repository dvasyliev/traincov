# Задача 06 — Прогноз: countdown і часові мітки

## Мета
Головна цінність продукту: за поточним км, швидкістю та профілем з розкладу порахувати **час прибуття в кожну точку попереду** і показати: «інтернет зникне через X хв, діра триватиме Y хв», плюс часові мітки на всій стрічці.

## Що працює після задачі
- Хедер Trip: `🟢 Онлайн ще 4:20 → далі ⛔ ~7 хв (тунель)` або `⛔ Мертва зона · ще ~2:10 до сигналу`.
- Кожна станція і зона на стрічці має прогнозний час (`~15:42`).
- Прогноз живе без GPS (деградація до розкладу).

## Кроки

### 6.1 core/eta.ts — модель часу
Чиста функція:
```ts
export interface EtaInput {
  km: number;                    // поточна позиція
  now: number;                   // Date.now()
  speedKmh: number | null;       // згладжена, з задачі 04
  confidence: 'gps'|'derived'|'none';
  stopped: boolean;
  bundle: RouteBundle;           // speedProfile, stops, deadZones
}
export interface EtaPoint { km: number; eta: number; }        // час прибуття, ms epoch
export interface EtaResult {
  timeline: EtaPoint[];                          // ETA для кожної станції і межі зони попереду
  nextZone: { zone: DeadZone; etaIn: number; etaOut: number } | null;
  inZone: DeadZone | null;
}
export function computeEta(i: EtaInput): EtaResult
```
Алгоритм — інтегрування по сегментах попереду:
1. Розбити [km → lengthKm] на сегменти за точками інтересу (межі speedProfile, станції, межі зон).
2. Швидкість сегмента:
   - перші `H = 3` км від поточної позиції — **бленд**: `v = w·vGps + (1-w)·vProfile`, де w лінійно спадає 1→0 по відстані (миттєва швидкість добре прогнозує близьке, розклад — далеке);
   - далі — чистий `vProfile` сегмента;
   - `confidence === 'none'` → одразу vProfile;
   - `stopped` на станції → додати планову стоянку `(dep - arr)`, але не більше залишку (якщо стоїмо довше плану — час «тече» в реальному часі).
3. `t += segKm / v`; накопичувати EtaPoint.
4. `nextZone` = перша зона з `fromKm > km`; `inZone` = зона, де `fromKm ≤ km ≤ toKm`.

### 6.2 Політика перерахунку
- Перераховувати на кожен GPS-фікс **і** таймером раз на 1 c (щоб countdown цокав рівно навіть між фіксами: між фіксами просто `etaIn - now`).
- computeEta — O(сегментів) ≈ десятки → можна дергати щосекунди без мемоізації, але сам розрахунок робити лише на фікс, а секундний тік — тільки віднімання.

### 6.3 Хедер-стан (стейт-машина відображення)
```
ONLINE_FAR    nextZone.etaIn > 10 хв → "🟢 Наступна діра через 38 хв (15:42)"
ONLINE_SOON   ≤ 10 хв               → великий mm:ss countdown + довжина/тривалість діри
IN_ZONE       inZone                 → "⛔ Мертва зона · сигнал за ~2:10" (countdown до toKm)
NO_ZONES      попереду чисто         → "🟢 До кінця маршруту дір не відомо"
NO_GPS        confidence none & !inZone → показувати розклад-only з позначкою "за розкладом"
```
- В IN_ZONE GPS може зникнути (тунель) → **dead reckoning**: продовжувати рух km за останньою швидкістю (`km += v·Δt`), позначка «оцінка». Це критично: саме в дірі користувач дивиться на екран найпильніше.
- Гістерезис на межах зон ±0.2 км, щоб стан не миготів від шуму.

### 6.4 Часові мітки на стрічці
- Біля кожної станції: прогнозний час (і плановий сірим, якщо розходяться > 3 хв).
- Біля кожної зони: `~15:42–15:49`.
- Оновлювати мітки не частіше разу на 10 c (перерендер списку дешевий, але нехай не смикається).

### 6.5 Сповіщення (мінімум)
- За 2 хв до зони: вібрація `navigator.vibrate(200)` (Android) + короткий звук (WebAudio, тихий) + флеш хедера. Web Notifications поза MVP (на iOS PWA вони вимагають установки на home screen — не зараз).
- Тумблер «попереджати про діри» в хедері.

### 6.6 Тест-набір (обов'язково юніт-тести, vitest)
computeEta — чиста функція, покрити:
- рівномірний рух без зупинок → ETA = відстань/швидкість;
- стоянка на станції додається;
- бленд GPS→профіль монотонний;
- зона попереду/всередині/позаду; зона рівно на станції;
- speed=null + confidence none → профіль;
- kmh профілю відсутній для сегмента → сусідній/дефолт 80.

## Обмеження
- Немає real-time запізнень PLK — прогноз «пливе» разом з фактичною швидкістю, що на практиці і є неявною корекцією запізнення.
- Тривалість діри рахується за швидкістю — у тунелі потяг зазвичай не гальмує, ок.
